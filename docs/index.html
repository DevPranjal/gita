gita.

— every agent needs a direction.

git was built for humans reading lines of text. But humans aren't the ones writing most code anymore — agents are. And agents don't want lines. They want answers.

gita is git rebuilt around the questions an agent actually asks.

what changes, for an agent

the shape of the answer

  • a 3-line summary instead of a 60-line diff — fewer tokens, faster triage
  • changes named by intent (add, body, signature, import +) — not re-derived from +/- hunks
  • no grep + sed as a substitute for "give me this function"
  • real ground truth for "did this commit pass?" — proven, not narrated

why this matters in a loop

  • less context bloat — structural summaries fit in tens of tokens, not thousands; long sessions stay coherent longer
  • fewer wrong turns — named ops (rename, signature, body) remove the guess-the-intent step before reasoning starts
  • self-verifying — gita prove + the auto-hook give the agent ground truth on its own commits, so it stops trusting its own commit messages
  • cheap regression hunts — bisect-proven reuses cached proofs instead of re-running the full suite at every step

01

"what changed in this commit?"

A real PR touches several things at once. git diff tells you which bytes moved. gita diff tells you which things moved — as a short list of named operations on named symbols.

git diffgit
$ git diff diff --git a/src/api.py b/src/api.py +from functools import lru_cache + +def rate_limit_check(uid): + ... def handle_get(req): - u = fetch_user(req.uid) + if not authorize(req): return 403 + u = fetch_user(req.uid, timeout=5) diff --git a/src/users.py b/src/users.py - class UserStore: + class UserRepo: diff --git a/src/jobs.py b/src/jobs.py - import os - import sys + import sys + import os diff --git a/config.yaml b/config.yaml - timeout: 30 + timeout: 60 # ~60 lines. agent has to read all of it to learn: was the import reorder meaningful? is UserStore→UserRepo a rename or a new class? did handle_get get an auth check or just get rewritten?
gita diffgita
$ gita diff manifest: 3 logic / 2 signature / 1 cosmetic op(s), 4 symbol(s) modified src/api.py add function rate_limit_check body handle_get: +4/-1 added auth guard import + functools (lru_cache) modified src/users.py signature fetch_user: added timeout param rename UserStore → UserRepo (3 ref(s)) modified src/jobs.py imports reordered (5 entries, no add/remove) modified config.yaml (non-python, textual diff) - timeout: 30 + timeout: 60 # the summary line alone tells the agent: "3 logic, 2 signature, 1 cosmetic." it can decide whether to read further before spending a token.

Op vocabulary is small and closed: add / remove / rename / signature / body / import + / import - / imports reordered / format. Non-Python files keep their unified diff, just labelled.

02

"show me this function."

The thing agents do twenty times an hour.

grep + sedgit
$ grep -rn 'def fetch_user' src/ src/users.py:40:def fetch_user(uid): $ sed -n '40,55p' src/users.py def fetch_user(uid): row = db.lookup('users', uid) ... # two commands. and you still have to guess where the function ends.
gita getgita
$ gita get fetch_user src/users.py:40-52 function fetch_user def fetch_user(uid): row = db.lookup('users', uid) if row is None: return None return User.from_row(row) # one call. exact bounds. methods work too: gita get UserHandler.put
03

"show it the way it was 5 commits ago."

Walks renames automatically — the symbol's old name is in the manifest chain.

checkout dancegit
$ git stash $ git checkout HEAD~5 $ grep -rn fetch_user src/ # (nothing — it was called get_user back then) $ grep -rn get_user src/ $ sed -n ... $ git checkout main && git stash pop # five commands. mutates your working tree. brittle.
gita get @revgita
$ gita get fetch_user@HEAD~5 src/users.py:38-49 function get_user # resolved as: get_user (renamed → fetch_user) def get_user(uid): row = db.lookup('users', uid) ... # one call. working tree untouched. rename followed.

"who calls this function?"
grepgit

05

"when was the last commit where tests passed?"

An agent that commits ten times an hour needs a real answer to this — not the commit message.

commit messagesgit
$ git log --oneline -5 a91f2c fix the thing 88e1d0 wip 3b22ff tests passing 🤞 7c0411 refactor 1d990a initial # commit messages lie. agents lie. nothing recorded the actual result.
gita prove + last-provengita
$ gita prove pytest -- python -m pytest -q ✓ pytest (exit 0, 1832 ms) $ gita last-proven pytest 3b22ff # refuses to run on a dirty tree. the proof can't lie about which commit it covers.
06

"every commit that touched this function."

History filtered to one symbol — and annotated with whether each commit was green.

git log -Sgit
$ git log -S fetch_user --oneline a91f2c fix the thing 88e1d0 wip 3b22ff tests passing # finds commits where the *string* changed count. misses renames. no shape.
gita symbol-loggita
$ gita symbol-log fetch_user ✓ a91f2c fix the thing body fetch_user: +2/-1 ✗ 88e1d0 wip signature fetch_user ✓ 3b22ff tests passing rename get_user → fetch_user (2 ref(s)) # follows renames. ✓/✗/· says which commits passed which check.
07

"which commit broke the tests?"

Bisect by a real criterion. Reuses cached proofs; only runs the check on commits it hasn't seen. Merges recurse one hop into the merged-in branch so the suspect is the real culprit, not the merge node.

git bisect rungit
$ git bisect start HEAD HEAD~20 $ git bisect run python -m pytest -q # re-runs your full test suite at every step from scratch. # no memory of which commits you already proved green.
gita bisect-provengita
$ gita bisect-proven pytest -- python -m pytest -q baseline 3b22ff (last green) walking 7 commits, running 2 (5 cached) suspect 88e1d0 wip signature fetch_user body handle_get: +4/-1 callers of fetch_user: src/api.py:12 in handle_get src/jobs.py:5 in run_batch # suspect sha + the structural ops + every caller of every touched symbol.
08

"re-run my checks after every commit."

No hand-rolled hooks. gita installs a post-commit hook once, then anything you've enabled gets re-proven on every new HEAD. The hook never fails the commit — a crashing check just shows up later as a ✗ glyph.

hand-rolled hookgit
$ cat > .git/hooks/post-commit <<'EOF' #!/usr/bin/env bash python -m pytest -q > /tmp/last.log 2>&1 || true echo "$(git rev-parse HEAD) $?" >> .git/passing.log EOF $ chmod +x .git/hooks/post-commit # now go invent your own way to query that log later.
gita hooks + autogita
$ gita hooks install ✓ installed post-commit hook $ gita auto enable pytest -- python -m pytest -q ✓ enabled: pytest # commit normally from now on. every HEAD gets proved. $ git commit -m "tweak" [post-commit] gita auto: pytest ✓ $ gita last-proven pytest a91f2c # queryable, structured, no log-parsing.

the same surface, for agents directly

A built-in MCP server exposes every command above as a tool. 

$ gita mcp

# in your agent's mcp config:
{
  "mcpServers": {
    "gita": {
      "command": "gita",
      "args": ["mcp"],
      "env": { "GITA_ROOT": "${workspaceFolder}" }
    }
  }
}

Nine tools: gita_diff · gita_status · gita_explain · gita_symbol_log · gita_callers · gita_get · gita_prove · gita_last_proven · gita_bisect_proven.
