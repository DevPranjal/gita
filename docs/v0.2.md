# gita v0.2

*— the long-running agent's read companion.*

v0.1 shipped `diff` / `explain` / `ask` over a content-addressed manifest
store. v0.2 finishes those three, then adds a fourth verb — `prove` — so the
agent can recall not just *what* it did but *which states were good*.

---

## customer

One customer. Everything else is parked.

> A single autonomous coding agent in hour 3 of a session (Claude Code, Devin,
> or similar). Long-running, many commits, fragile context window. Its bleeding
> wound is **re-reading history** without re-loading source.

Not the customer for v0.2:

- Inline / one-shot edit agents — already hold the file, marginal benefit.
- Agent swarms — multiverse branching is a v0.4 conversation at best.
- Maintainer / review agents — they want intent metadata, which is parked.

---

## what v0.1 already does

| verb     | does                                                                   |
| -------- | ---------------------------------------------------------------------- |
| `diff`   | structural diff between any two refs (rename-aware, similarity ≥ 0.6). |
| `explain`| replays the stored manifest for a commit.                              |
| `ask`    | `symbol-log <sym>` and `callers <sym>` over the manifest index.        |
| `mcp`    | stdio JSON-RPC surface for all of the above.                           |

v0.2 does **not** redesign these. It fills three concrete gaps and adds one
new verb.

---

## 01 · `ask` — fill the snapshot gap

Today the agent can walk a symbol's *history* but cannot ask *"what does
`fetch_user` look like right now?"* without reading the file. Closing that
gap is the single highest-leverage addition.

```sh
gita get fetch_user                 # current shape at HEAD
gita get fetch_user@HEAD~3          # historical shape
gita get fetch_user@a9b54e1 --json  # for the agent
```

Returns: signature, docstring, body, defining file + line range, and the
symbol kind (`function`, `method`, `class`).

```text
$ gita get fetch_user
function fetch_user  [src/users.py:14-22]
    def fetch_user(uid: str) -> User | None:
        """Look up a user by id, caching on hit."""
        row = db.lookup('users', uid)
        if row is None:
            return None
        return User.from_row(row)
```

**Resolution rules** (pick one, document it, never deviate):

- Bare name (`fetch_user`) resolves uniquely if there's one symbol with that
  name across the tree. Otherwise it errors and lists qualified candidates.
- Qualified name (`users.fetch_user`, `UserHandler.get`) always wins.
- `@rev` walks the manifest chain — including renames — so
  `gita get fetch_user@HEAD~5` correctly returns the body of what was then
  called `get_user`.

## 02 · `diff` — sharpen the filter

Two narrow additions:

```sh
gita diff HEAD~3 HEAD --symbol fetch_user   # only ops touching this symbol
gita diff --json                            # mark non-parseable files explicitly
```

The JSON output gains a `parseable: false` flag on file entries that fell
back to textual diff, so an agent doesn't silently mistake "no structural
ops" for "no change."

```json
{
  "path": "config.yaml",
  "status": "modified",
  "parseable": false,
  "textual_diff": "..."
}
```

No new parsers in v0.2. Tier-1 = Python (already). Everything else stays
textual-fallback and says so.

## 03 · `prove` — net-new pillar

The reason this exists: a long-running agent commits often. Some commits
pass tests, some don't, some were checkpointed mid-thought. When the session
compacts or resumes, the agent has no way to ask *"what's the last commit
where the auth tests passed?"* — git treats every commit as equal.

`prove` records check results against a commit. `last-proven` queries them.

### record

```sh
gita prove pytest -- python -m pytest tests/auth
gita prove mypy   -- mypy src/
```

Runs the command, captures exit code + truncated output, stores under
`.git/gita/proofs/<commit_sha>.json`:

```json
{
  "commit": "a9b54e1…",
  "checks": {
    "pytest": {
      "ok": true,
      "exit_code": 0,
      "duration_ms": 4218,
      "ran_at": "2026-05-26T12:08:14Z",
      "cmd": ["python", "-m", "pytest", "tests/auth"],
      "stdout_head": "...",
      "stdout_tail": "...",
      "truncated": true
    }
  }
}
```

Captured output is bounded: 4 KB head + 4 KB tail, with `truncated: true`
when trimmed. Anything larger goes to the agent's own logs, not gita's.

### query

```sh
gita last-proven                    # last commit where every recorded check is ok
gita last-proven pytest             # last commit where 'pytest' specifically was ok
gita last-proven --symbol fetch_user pytest
                                    # last commit where this symbol existed AND pytest passed
```

The third form is the one that pays for the whole pillar: it lets a resumed
agent ask *"give me the last known-good state of the thing I'm working on,"*
which is structurally impossible in git today.

### display

`explain` and `symbol-log` surface proof status inline:

```text
$ gita symbol-log fetch_user
a9b54e1  ✓ pytest  rename get_user, add caching
710c2f3  ✗ pytest  faster lookup
d04a811  ·         initial users module     (no proofs recorded)
```

`·` = unknown, `✓` = all recorded checks ok, `✗` = at least one recorded
check failed. Three states, never two — "no proof" is not "fail."

### what `prove` deliberately is *not*

- Not a CI runner. It runs a command and records the result. Scheduling,
  matrix builds, artifact storage are out of scope forever.
- Not signed / cryptographic. Proofs are local hints, not attestations.
- Not retroactive. Proofs attach to the commit that's currently `HEAD` when
  `prove` runs; you can't prove a commit you don't have checked out.
- Not tree-keyed. Proofs are commit-keyed. Editing the working tree
  invalidates nothing because nothing is bound to the tree. Cleaner mental
  model, monotone storage.

## storage

New layout under `.git/gita/`:

```
.git/gita/
  manifests/<commit_sha>.json     # unchanged from v0.1
  callers/<tree_sha>.json         # unchanged from v0.1
  proofs/<commit_sha>.json        # new
```

No migration needed. Proofs are additive; existing repos keep working with
empty proof state.

## mcp surface

New tools on the stdio server:

| tool                | maps to                                      |
| ------------------- | -------------------------------------------- |
| `gita_get`          | `gita get <symbol>[@rev]`                    |
| `gita_prove`        | `gita prove <name> -- <cmd>`                 |
| `gita_last_proven`  | `gita last-proven [<name>] [--symbol <sym>]` |

Existing tools (`gita_diff`, `gita_status`, `gita_explain`, `gita_symbol_log`,
`gita_callers`) gain the parameters their CLI counterparts gain — nothing
removed.

## non-goals for v0.2

Spelled out so they stop showing up in design discussions:

- **Intent metadata on commits.** Requires write-side adoption that does
  not exist. Revisit in v0.3 once `prove` has users.
- **Symbol-scoped edit ops** (`gita rename foo bar`). Only worth it once an
  agent SDK exists that would emit them. Today, mutations enter gita by
  AST-diffing whatever the agent committed via regular git — and that's
  the right floor.
- **Speculative / multiverse branching.** Wrong customer.
- **Cryptographic agent identity.** Solving a problem we don't have.
- **Cross-language parsing past Python.** Tier-2 stays textual-fallback.

---

## open questions

Flagging for review, not blocking:

1. **`gita get` on overloaded names** — if `__init__` exists in 14 classes,
   should bare `gita get __init__` list candidates or refuse? Current
   proposal: refuse + list. Easy to relax later, hard to tighten.
2. **Proof retention** — proofs are tiny (~1 KB each) but unbounded. Do we
   GC proofs for commits unreachable from any ref? Proposal: yes, on a
   `gita gc` command, opt-in only.
3. **`last-proven` with no recorded proofs** — return nothing (silent) or
   error with a hint? Proposal: error with hint; silent is the worst answer
   for an agent that just lost its tool's output.

---

## done means

v0.2 is shippable when:

- `gita get <symbol>[@rev]` returns the symbol's shape across renames.
- `gita diff --symbol` and `parseable: false` ship in CLI + JSON + MCP.
- `gita prove` records, `gita last-proven` queries, both with `--symbol`
  filter.
- `symbol-log` and `explain` show three-state proof glyphs.
- Tests cover: snapshot retrieval across renames; proof storage round-trip;
  `last-proven --symbol` skipping commits where the symbol didn't exist;
  the three-state display.
