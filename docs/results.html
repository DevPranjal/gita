Does it actually work?

Ten tasks across Flask, Express, Gin, ripgrep and got. Two arms: a coding agent with plain git, and the same agent with gita also on PATH. gita is never mentioned in the prompt — it has to be discovered and chosen, or it does not count.

110 runs — six repetitions of every task in both arms. Eight of ten tasks come out cheaper.

how it is measured

The agent is not told

gita is put on PATH and described in the repository's AGENTS.md exactly as any other repo tool would be. The task prompt never names it. If the agent does not find it useful, it does not use it, and that counts against gita.

Cost is real, not a proxy

Priced in credits from the model's own logs, across four token classes that differ in price by 50x. Token totals mislead in both directions: fresh output is billed at up to 12.5x the rate of cached context.

Quality is scored as entity recall — whether the agent's final answer names the things the change actually touched. A cheaper answer that misses the point is not a win, so cost is only ever read next to recall.

how to read these numbers

Turn count and tool output are the steady signals; the cost figure is the imprecise one. It carries a 95% interval of −4% to −30%: real, but ten tasks differ from each other far more than repetitions of one task do, so the aggregate can only be resolved so far. Turns matter most anyway, because a turn re-sends the entire context.

Recall is reported at 99% against git's 100%, which is not rounded away.
