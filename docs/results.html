Does it actually work?

Eighteen tasks across Flask, Express, Gin, ripgrep and got. Two arms: a coding agent with plain git, and the same agent with gita also on PATH. gita is never mentioned in the prompt — it has to be discovered and chosen, or it does not count.

216 runs across two sweeps. The cost figure is quoted after discarding runs that lost the prompt cache — noise priced at 12.5×, unrelated to either tool — and carries a 95% interval of −3% to −25%, bootstrapped over tasks. The two sweeps read −16.7% and −11.2% on their own and cannot be told apart by this harness, so they are pooled and both are shown rather than the better one being picked.

two claims that did not survive more data

This page previously reported tool output −92%, from ten tasks. On eighteen it read +0.4%, and pooled across two sweeps it reads −46%. A number that swings that far with the sample is not measuring the tool, so it is no longer a headline claim. The original figure had been carried by a single lockfile task.

It also reported −15.4% as the headline. That point estimate compared arm totals while the interval printed beside it paired by task. On a balanced sweep the two agree exactly, which is how the discrepancy survived fourteen sweeps. Paired, those same runs read −17.9%.

One benchmark task was corrected too: its answer key demanded the name of a test that the commit deletes. Both arms named the added test and both were marked down, so the fix moves both from 50% to 100% and cannot favour either.

All three are recorded rather than quietly dropped, because a benchmark that only ever revises upward is not a benchmark.

how it is measured

The agent is not told

gita is put on PATH and described in the repository's AGENTS.md exactly as any other repo tool would be. The task prompt never names it. If the agent does not find it useful, it does not use it, and that counts against gita.

Cost is real, not a proxy

Priced in credits from the model's own logs, across four token classes that differ in price by 50x. Token totals mislead in both directions: fresh output is billed at up to 12.5x the rate of cached context.

Quality is scored as entity recall — whether the agent's final answer names the things the change actually touched. A cheaper answer that misses the point is not a win, so cost is only ever read next to recall.

how to read these numbers

Turn count is the steady signal; the cost figure is the imprecise one. Cost carries a 95% interval of −3% to −25% after cache-noise is removed — real, but eighteen tasks differ from each other far more than repetitions of one task do, so the aggregate can only be resolved so far. Turns matter most anyway, because a turn re-sends the entire context.

Tool output is not reported as a headline. It read −92% on ten tasks, +0.4% on eighteen, and −46% pooled across two sweeps. A number that swings that far with the sample is measuring the sample, not the tool.

Recall is 99.5% for git and 99.7% for gita, after correcting one task whose answer key demanded the name of a test its commit deletes. Both arms had named the added test and both were marked down, so the fix moves both from 50% to 100% and leaves the comparison unchanged.
