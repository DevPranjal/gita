gita.

— every agent needs a direction.

git, rebuilt for a world of agent coders. When a coding agent needs to understand a change, it runs git diff and reads every changed line — a wall of text, most of it irrelevant, and it pays for all of it again on every step that follows. gita answers the question instead: which functions changed, and does anything break?

One command. Never larger than the git diff it replaces. v1.0.0 · Python 3.11+ · 465 tests · MIT

the problem, plainly

what goes wrongwhywhat gita does
the answer is buried A diff is ordered by file, not importance. The function that broke sits inside 400 lines, and models attend least to the middle of a long input. Ranked output. Interface breakage first, and short enough to have no middle.
most of it is not the change Reformatting, reordered imports, three unchanged lines around every edit. Removed by comparing normalised hashes, with the count reported.
the formatting itself costs Per-line +/-, filenames repeated per chunk, 40-char hashes. Measured: +25% tokens, 20 tokens per commit hash. Entity ids, filenames once, no hashes in the body.
you pay again every step Tool output is re-sent on every later step: 16,713 tokens over five steps is 83,565. 3,969 over the same five steps is 19,845 — and it usually needs fewer steps.
it causes real mistakes Deleted code stays visible and gets called again; one lockfile diff fills the window. Deletion is a fact ([removed]), not lingering source. Hard budget: a dependency update goes 220,377 → 2,203.

the surface

everything gita doescli
$ gita diff uncommitted work, untracked files included $ gita diff HEAD^ HEAD one commit $ gita diff main HEAD a branch or PR range $ gita show <name> exact hunks for one entity $ gita history <name> how one function changed, with the code $ gita expand <id> open a rolled-up line $ gita serve MCP server --interface-only only changes that can break a caller --patch plain unified diff, noise removed --filter TERM narrow by name or path --budget N hard cap, honoured exactly --json machine-readable

Three ways in: the CLI, an MCP server (gita_diff, gita_show, gita_expand), and a typed Python API of 14 exports. Bare names work — gita history fetch. Ambiguity is reported, never guessed. git's spellings are accepted where they mean the same thing: --stat, --oneline, --base/--head, --no-pager.

the engine · deterministic core, probabilistic garnish

Every fact gita reports is computed. No model decides what changed. A model may one day improve the prose of a summary line; it may never supply a fact. The design target is that gita degrades to worse prose, never to wrong facts.

01
git objects
Changed paths from tree comparison; blobs streamed through one cat-file --batch process.
02
parse
tree-sitter builds an entity tree per revision. Cached by content, so the same bytes are parsed once.
03
match
Sibling groups, then stable id, then content hash, then similarity — four passes, most specific first.
04
classify
Four hashes per entity decide cosmetic vs body vs interface change, as a fact rather than a guess.
05
compose
Rank, roll up, and fill a token budget measured on the text actually emitted.

The entity model

An entity is a named thing with a stable id — path::Parent::child — and four hashes. The hashes are what make noise filtering deterministic rather than heuristic.

hashcoverswhat a difference means
raw_hashexact bytesany edit at all
content_hashcomments stripped, whitespace normalised raw differs but this matches ⇒ cosmetic
signature_hashas above, body excluded differs ⇒ a caller can break
body_hashas above, body only identity under rename and move

An entity owns only the tokens no descendant entity claimed, so a class does not report a change every time one of its methods does. Tokens are collected gap-aware — tree-sitter gives a TOML string two quote children with the value in the gap between them, and taking only leaves once made a dependency version bump hash as unchanged.

Identity is not position

url, url#2, url#3 are slots among same-named siblings. Insert one member and every later one shifts, so matching by id reported untouched members as edited — three changes where the truth was one addition.

Sibling groups are now resolved together, by content before position. Measured over 125 commits of five real repositories, renumbering false alarms fell 25 → 14.

The budget is a contract

--budget N is a hard cap, and the answer is never larger than the raw git diff it replaces — so adopting gita cannot cost more than not adopting it.

Both are enforced against the text as assembled, not the sum of its parts: a missed separator once put an answer one token over. Swept across every budget from 1 to 400 — no violations.

performance · use the plumbing

Answering “how did this function change over twenty commits” once took 12s, of which 6.5s was 98 git subprocesses at ~67ms of spawn each. Parsing was not the bottleneck; asking was. Three fixes, each git's own answer: prune by tree before opening files, stream objects through one cat-file --batch, and walk commits once with --name-status instead of twice per commit.

evidence · measured against a live agent

Ten tasks across Flask, Express, Gin, ripgrep and got. Two arms: an agent with plain git, and the same agent with gita also on PATH. gita is never mentioned in the prompt — it has to be discovered and chosen, or it does not count. Cost is priced in real credits from the model's own logs.

adoption, unprompted—98%

Read the cost figure as a band. 110 runs, six repetitions per task per arm, with prompt-cache-miss runs excluded — one miss costs two to three times a normal task and says nothing about either tool. Eight of ten tasks come out cheaper.

A control sweep that repeated the previous one with byte-identical behaviour moved the headline ten points, and one task moved 82. At three repetitions per-task cost numbers are noise. Turn count and tool output are the steady signals; cost is the noisy one.

what gita does not do

  • No call graph. unreferenced is name matching: it catches dead code, not dependents. Labelled as such wherever it appears.
  • No “what should I re-test?” That needs real caller edges. gita refuses rather than guesses.
  • No natural-language questions. An earlier ask() was withdrawn for degrading to confidently wrong instead of bluntly right.
  • Prose diffing is structural only — sections and keys, not meaning.
  • Bulk tests are summarised when they accompany source changes; --filter expands them.

how it was built

The cost number is a bug detector

Every cost regression turned out to be a correctness defect wearing a cost disguise: an encoding crash on a Windows pipe, history that said when but not what, Rust impl Trait for Type losing the trait, 159 test names burying the one API change asked about.

The quality number is a better detector still. One recall miss led to finding that TOML and YAML value changes were classified as cosmetic — gita was answering “no material changes” for a dependency version bump.

Equivalence, not hope

Every fast path keeps its slow path behind a flag so tests can prove they agree. The hashing refactor was checked by fingerprinting 1,433 entities from five real repositories under both implementations — identical digest.

Three v1 defects were found by installing the wheel and running it, not by the 433 tests then passing. A step that moves no number gets deleted.
