What we are building

One command that answers what changed, which functions and files it touched, whether the public interface broke, and only the code that matters — with formatting noise removed, inside a token budget, and never larger than the git diff it replaces.

how a change is held

A file is parsed into entities — named things with a stable id like src/app.py::Store::get — and each entity carries four hashes. Comparing hashes is what makes noise filtering a fact instead of a guess.

hashcoversa difference means
raw_hashexact bytesany edit at all
content_hashcomments stripped, whitespace normalised raw differs but this matches ⇒ cosmetic only
signature_hashas above, body excluded differs ⇒ a caller can break
body_hashas above, body only identity survives a rename or a move

So signature_changed is not an inference about what probably matters — it is a statement that the declaration hashes differently. An entity owns only the tokens no nested entity claimed, so a class does not report a change every time one of its methods does.

two promises

Never larger than git

The answer is capped by the raw git diff it replaces, so adopting gita cannot cost more than not adopting it. On small diffs it comes out about the same size; the wins concentrate where the pain is.

Enforced against the text as assembled, at every budget value.

Exact, or it says so

--budget N is a hard cap. If something was dropped to fit, the output says so and names what is missing, so a follow-up is a choice rather than a surprise.

Ambiguity is reported, never guessed: a bare name that matches two entities returns both rather than picking one.

what it runs on

Python, JavaScript, TypeScript, TSX, Go and Rust, plus structural handling of Markdown, YAML, JSON and TOML. Unsupported files degrade to a whole-file entity rather than vanishing — a silent omission reads as “unchanged”, which would be a wrong fact.

Parsing is tree-sitter; token counting is tiktoken, so a budget matches what an agent actually pays. Three ways in: a CLI, an MCP server, and a typed Python API.

what gita does not do

  • No call graph. The unreferenced check is name matching: it catches dead code, not dependents. Labelled as such wherever it appears.
  • No “what should I re-test?” That needs real caller edges. gita refuses rather than guesses.
  • No natural-language questions. gita reports facts it computed and refuses questions it cannot answer exactly.
  • Prose diffing is structural only — sections and keys, not meaning.
  • Bulk tests are summarised when they accompany source changes; --filter expands them.
