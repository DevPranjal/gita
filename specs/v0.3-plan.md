# gita v0.3 — implementation plan

Same rhythm as v0.2: TDD per phase, every phase independently shippable,
refactors only when the third caller arrives.

v0.2 landed at 116 tests. v0.3 aims for ~155.

---

## phase 1 · `gita context <symbol>` (composite read, no new data)

**Why now:** highest-frequency MCP call in the v0.3 flow. Pure
composition over verbs that already exist; lands fast.

**Tests to add** — `tests/test_gita_context.py` (new):

- `test_context_returns_symbol_callers_log_proven` — symbol exists,
  has callers, has history, has a proven commit. Result dict contains
  all four sections.
- `test_context_symbol_not_found_raises` — `NotFound` propagates up
  from `lookup.get` unchanged.
- `test_context_no_callers_returns_empty_list` — `callers: []`, not
  missing key. Predictable shape for agents.
- `test_context_no_proofs_returns_none_for_last_proven` —
  `last_proven: None`, not a `NoProofs` exception. Context is
  read-only and best-effort.
- `test_context_history_limit_default` — without `--budget`, log is
  capped at the last 10 commits touching the symbol.
- `test_context_budget_drops_oldest_log_first` — `--budget` low enough
  to cut log; signature + body + first-failing + last-proven survive,
  oldest log entries drop.
- `test_context_budget_drops_callers_before_body` —
  signature + body are atomic and survive even brutal budgets;
  callers go before they're touched.
- `test_context_budget_zero_keeps_signature_only` — degenerate case;
  always returns at least the signature.
- `test_context_at_rev` — `context(root, "fetch_user", rev="HEAD~2")`
  composes from that rev, not HEAD.

**Tests to add** — `tests/test_gita_cli.py`:

- `test_cli_context_text` — sections render in fixed order with
  blank-line separators.
- `test_cli_context_json` — keys: `symbol`, `callers`, `log`,
  `last_proven`. Each section is its own object/array.
- `test_cli_context_budget_flag` — `--budget 500` reduces output.

**Code:**

- `src/gita/context.py` (new):
  - `ContextRecord` dataclass with sections.
  - `build(root, name, *, rev="HEAD", budget=None, log_limit=10) -> ContextRecord`:
    1. `symbol = lookup.get(root, name, rev=rev)`.
    2. `callers = callers.lookup(root, name, rev=rev)`.
    3. `log = history.symbol_log(root, name, rev=rev)[:log_limit]`.
    4. `last_proven = proofs.last_proven(root, symbol=name)` swallowing
       `NoProofs` → `None`.
    5. If `budget`, run `_fit(record, budget)` which drops sections in
       a fixed order: oldest log entry → second-oldest → callers →
       last_proven → body (only if budget is genuinely 0). Signature is
       never dropped.
- `src/gita/cli.py` — `_cmd_context`, text + JSON renderers.

**Refactor in this phase:** if and only if `history.symbol_log` doesn't
already exist as a public function, lift it out of `_cmd_symbol_log`.
(Currently it likely lives in CLI glue; promote it to `history.py`.)

**Acceptance:** all new tests green; `gita context build_for_refs` on
this repo produces a clean three-section view.

## phase 2 · `gita bisect-proven` (the headline)

**Why now:** the largest pillar. Depends on phases 0 (json) and 1
(callers section is reused for the reporting structure) only loosely;
could ship after either.

**Tests to add** — `tests/test_gita_bisect.py` (new):

- `test_bisect_no_baseline_raises` — proofs dir empty for `pytest`
  check → `NoBaseline` exception listing the check name.
- `test_bisect_head_is_baseline_returns_clean` — `last_proven == HEAD`
  → returns `BisectResult(suspect=None, reason="head_is_proven")`.
- `test_bisect_head_passes_with_cmd_records_and_returns_clean` —
  `bisect(... cmd=[...])` runs the cmd on HEAD; if it passes, records
  the proof and returns clean.
- `test_bisect_over_cached_proofs_narrows_to_first_failure` — three
  commits between green and HEAD, middle one has `pytest: fail` proof;
  result's suspect is the middle commit. No subprocess called.
- `test_bisect_fills_gaps_with_cmd` — proofs only on endpoints; with
  `cmd=[...]` provided, runs cmd on each intermediate, records proofs,
  narrows to first failure. Without `cmd`, returns
  `BisectResult(suspect=None, reason="gaps", missing=[shas])`.
- `test_bisect_reports_ops_from_suspect_manifest` — suspect's manifest
  has `[body fetch_user, add helper_x]`; result `ops` field contains
  both, each with full op dict.
- `test_bisect_symbol_filter_drops_unrelated_ops` — `--symbol foo`;
  ops touching only `bar` are filtered out of the report. The suspect
  commit itself is unchanged.
- `test_bisect_merge_commit_recurses_one_hop` — suspect is a merge;
  result recurses into the merged-in side and reports the suspect from
  that side, with `via_merge: <merge_sha>` annotation.
- `test_bisect_dirty_tree_with_cmd_refuses` — `cmd` provided but
  working tree dirty → exits with hint. (We need to checkout commits;
  can't lose state.)
- `test_bisect_restores_head_after_running_cmd` — even on cmd failure
  mid-walk, `HEAD` and working tree match starting state when verb
  returns.
- `test_bisect_records_proofs_for_commits_it_ran` — after a run
  with gaps filled, those commits have `prove` files on disk.

**Tests to add** — `tests/test_gita_cli.py`:

- `test_cli_bisect_proven_text_output` — happy path; shows
  `range:`, `suspect:`, ops, `hint:` lines.
- `test_cli_bisect_proven_json_output` — schema per spec.
- `test_cli_bisect_proven_exits_nonzero_on_no_baseline` — exit 3,
  same code as `last-proven` empty for consistency.

**Code:**

- `src/gita/bisect.py` (new):
  - `BisectResult` dataclass: `{from_sha, to_sha, suspect, ops,
    callers_of_changed_symbols, checks_used, via_merge}`.
  - `NoBaseline` exception.
  - `run(root, name, *, cmd=None, symbol=None, ref="HEAD") -> BisectResult`:
    1. `from_sha = proofs.last_proven(root, name=name)` (raises
       `NoBaseline` if empty).
    2. If `from_sha == HEAD` → clean result.
    3. If `cmd`: run on HEAD first; on pass, record proof + clean.
    4. Walk `gx.log_shas(from_sha..HEAD)` newest-to-oldest. Per
       commit, pull cached proof or (if `cmd`) checkout + run +
       record + restore. Track first failing.
    5. If walk has unresolved gaps and no `cmd` → return reason
       `"gaps"` with missing shas; don't guess.
    6. Read suspect's manifest via `store.read`; assemble ops,
       optionally filtered by `symbol`.
    7. Pull caller info for symbols mentioned in the ops via
       `callers.lookup` at the suspect's tree.
    8. If suspect is a merge commit, recurse one hop into the
       merged-in branch; preserve `via_merge`.
  - All checkouts go through a context manager that captures
    `HEAD` + working-tree state at entry and restores on exit
    (success or exception).
- `src/gita/cli.py`:
  - `_cmd_bisect_proven` — text + JSON; maps `NoBaseline` to exit 3
    with hint identical to `last-proven` empty.
- `src/gita/_manifest.py` / `src/gita/git.py`:
  - Add `gx.is_merge_commit(root, sha) -> bool` if not present.
  - Add `gx.merge_parents(root, sha) -> list[str]` if not present.

**Refactor in this phase:** the checkout-and-restore context manager
will get reused by phase 3's auto-prove hook tests; promote it to
`src/gita/git.py` as `checkout_then_restore(root, sha)` from day one.
Two callers in this PR justify it.

**Acceptance:** all new tests green; smoke test by hand on this repo:
break a test deliberately, commit twice, run `gita prove pytest -- ...`
on the pre-break commit, then `gita bisect-proven pytest`.

## phase 3 · auto-prove post-commit hook (opt-in)

**Why now:** depends on phase 2 conceptually (proofs as substrate for
bisection) but technically independent. Small surface.

**Tests to add** — `tests/test_gita_hooks.py` (new):

- `test_install_hooks_writes_post_commit` — `hooks.install(root)`
  creates `.git/hooks/post-commit`, marks it executable, writes the
  sentinel `.git/gita/hooks-installed`.
- `test_install_hooks_refuses_to_clobber_existing_unrelated_hook` —
  existing `post-commit` without gita's marker → exit non-zero with
  hint to inspect or pass `--force`.
- `test_install_hooks_force_replaces` — `--force` overwrites; backup
  written next to it as `post-commit.bak`.
- `test_uninstall_hooks_removes_only_gita_section` — installed hook
  is removed; non-gita hook content preserved if present (use marker
  block).
- `test_proofs_config_defaults_no_auto` — fresh repo,
  `proofs.read_config(root)` returns `{checks: {}}`.
- `test_proofs_config_marks_check_auto` — `proofs.set_auto(root,
  "pytest", auto=True)` updates config.
- `test_auto_prove_runs_only_auto_checks` — config has
  `pytest: auto`, `mypy: not auto`; previous HEAD had both. Run the
  hook on a new commit → new proofs file has `pytest` (newly run) and
  carries forward `mypy` from the parent (if present), or omits it
  (decide now: **carry forward**, so `last-proven` semantics stay
  monotone).
- `test_auto_prove_no_auto_checks_is_noop` — empty auto-list → hook
  exits 0, no proof file written.
- `test_auto_prove_failure_records_failure_not_exit` — hook itself
  exits 0 even if `pytest` fails (otherwise `git commit` errors).
  Proof file records `ok: false`.

**Tests to add** — `tests/test_gita_cli.py`:

- `test_cli_install_hooks` — happy path.
- `test_cli_proofs_auto_set` — `gita proofs auto pytest --on` /
  `--off` round-trips.

**Code:**

- `src/gita/hooks.py` (new):
  - `MARKER_START = "# gita-auto-prove:start"`,
    `MARKER_END = "# gita-auto-prove:end"`.
  - `install(root, *, force=False) -> None`.
  - `uninstall(root) -> None`.
  - The installed hook script is a one-liner:
    `python -m gita _auto_prove_hook` (no shell scripting in-tree).
- `src/gita/proofs.py`:
  - `read_config(root)` / `write_config(root, cfg)`.
  - `set_auto(root, name, auto: bool)`.
  - `auto_prove_for_head(root)` — the function the hook invokes.
    Reads config, runs each auto check, merges with carry-forward
    from parent's proof file.
- `src/gita/cli.py`:
  - `_cmd_install_hooks`, `_cmd_uninstall_hooks`.
  - `_cmd_proofs_auto` — `gita proofs auto <name> --on|--off`.
  - Internal entry point `_cmd_auto_prove_hook` (hidden from
    `--help`; exposed only via `python -m gita`).

**Refactor in this phase:** none. Don't try to unify `proofs.record` and
`auto_prove_for_head` yet; they share `_run_one` already.

**Acceptance:** install hook in this repo; mark `pytest` auto; make a
trivial commit; verify the new commit gets a `pytest` proof
automatically. Uninstall; verify hook gone; nothing else touched.

## working rhythm

Unchanged from v0.2:

1. Write every test stub for the phase first, all red.
2. Make the first one green with the smallest slice. Commit.
3. Next. Repeat.
4. End of phase: green suite, no `# todo`, no dead branches. Refactor
   only what now has three callers.

Commit message convention:

```
phase N: <verb-or-module>: <one-line summary>
```

e.g. `phase 2: bisect: narrow over cached proofs`,
`phase 3: hooks: install opt-in post-commit auto-prove`.

## not in this plan (explicit)

- Structural merge / op composition (v0.4 headline).
- Multi-language parsing past Python (v0.3.1 or v0.4).
- Multiverse / speculative branches (still wrong customer).
- Cryptographic signatures on `who` (still solving a problem we don't
  have).
- README + web page updates. Same rule as v0.2: rewrite once, after
  phase 4 ships, by someone who used `bisect-proven` in anger.
