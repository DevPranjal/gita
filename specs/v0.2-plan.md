# gita v0.2 — implementation plan

TDD throughout: every phase is *write tests → run red → implement → green →
refactor*. Each phase is independently shippable and ends green, so you can
stop after any phase and still have a usable release.

Refactors live inside the phase that needs them, not as a separate phase up
front. Don't refactor what nothing uses.

---

**Code:**

## phase 1 · `diff --symbol` + `parseable: false`

**Why now:** smallest user-visible win, no schema-breaking changes, exercises
the parse module just refactored.

**Tests to add** — `tests/test_gita_symdiff.py` and `tests/test_gita_cli.py`:

- `test_diff_filters_to_one_symbol` — manifest with ops on `foo` and `bar`; `--symbol foo` keeps only ops mentioning `foo` (including as `from`/`to` in renames).
- `test_diff_filter_drops_empty_file_entries` — files with no surviving ops vanish from the filtered output (parallel to existing `--only`/`--exclude` behavior).
- `test_diff_filter_keeps_added_and_deleted_files_if_symbol_matches` — added/deleted file with `foo` defined survives; same file without `foo` is dropped.
- `test_nonpy_file_marked_parseable_false` — modify a `config.yaml`; manifest file-entry has `parseable: false` and `textual_diff` populated; no `ops` array.
- `test_nonpy_file_unchanged_is_omitted` — non-Python file with no change is *not* in the manifest (no noise).
- `test_cli_diff_symbol_flag` — `gita diff --symbol fetch_user` exits 0, prints filtered text + JSON.

**Code:**

- `src/gita/diff.py`
  - `_collect_tree_text` → `_collect_tree_files` returning `dict[str, FileBlob]` where `FileBlob` carries `text` + `parseable: bool` (set from extension for now; later from a content sniff).
  - `_collect_working_tree` / `_collect_staged_tree` — same treatment.
  - `build_for_trees` — for `parseable=False` paths, emit `{path, status, parseable: False, textual_diff}` instead of running through `diff_sources`.
- `src/gita/symdiff.py` — leave alone; only sees parseable inputs.
- `src/gita/_manifest.py` — schema bump 1 → 2; `build_manifest` writes `schema: 2` and tolerates the new `parseable: false` shape.
- `src/gita/cli.py` — `_filter_manifest` gains a `symbol: str | None` parameter; `diff` subcommand grows `--symbol NAME` flag.
- `src/gita/_manifest.py:render_manifest` — render `parseable: false` files as `modified   <path>   (non-python, textual diff)` followed by an indented head of the textual diff (truncated to ~20 lines so the human-readable view stays readable; JSON keeps full).

**Refactor in this phase:** remove the `_manifest` re-exports added in phase 0 — `symdiff` and tests now import from `parse` directly. Search and delete the shim block.

**Acceptance:** existing tests pass after schema bump (update any literal `"schema": 1` assertions); new tests green; `gita diff --json` includes `parseable: false` on a YAML edit.

## phase 2 · `gita get <symbol>[@rev]`

**Why now:** the substrate gap. Largest pillar. Must come before `prove` because `last-proven --symbol` depends on knowing when a symbol existed.

**Tests to add** — `tests/test_gita_lookup.py` (new):

- `test_get_function_at_head` — file with `def fetch_user(uid): ...`, `lookup.get(root, "fetch_user")` returns `Symbol(name="fetch_user", kind="function", path="src/users.py", line_start=1, line_end=2, signature="def fetch_user(uid):", body="...")`.
- `test_get_class_at_head` — `class User: ...` returns `kind="class"`.
- `test_get_method_qualified` — `UserHandler.get` resolves to the method, not the top-level `get`.
- `test_get_method_bare_when_unique` — only one `__init__` in tree → bare name resolves it.
- `test_get_ambiguous_bare_name_lists_candidates` — two `__init__` methods → `Ambiguous` raised, candidates include `User.__init__` and `Admin.__init__`.
- `test_get_unknown_symbol_raises_not_found` — `NotFound` carries the searched name.
- `test_get_at_rev` — commit A defines `foo`, commit B deletes it. `lookup.get(root, "foo", rev="A")` returns the symbol; `lookup.get(root, "foo", rev="B")` raises `NotFound`.
- `test_get_walks_rename_backward` — commit A: `def get_user(): pass`. Commit B: rename to `fetch_user`. `lookup.get(root, "fetch_user", rev="A")` returns the symbol *under its old name `get_user`* (the same identity, walked back through the manifest chain). Result carries both `name="get_user"` and `requested_as="fetch_user"`.
- `test_get_does_not_walk_forward_renames` — `lookup.get(root, "get_user", rev="B")` raises `NotFound`. (Walking forward through renames is symmetric and tempting, but agents asking for the *current* name typically mean HEAD; symmetry can come in v0.3 if real users need it.)

**Tests to add** — `tests/test_gita_cli.py`:

- `test_cli_get_prints_symbol` — `gita get fetch_user` exits 0, shows file path + line range + body.
- `test_cli_get_json_shape` — `--json` returns `{name, kind, path, line_start, line_end, signature, body, rev, requested_as}`.
- `test_cli_get_ambiguous_exits_nonzero_with_candidates` — exit 2, stderr lists qualified candidates.
- `test_cli_get_not_found_exits_nonzero` — exit 1, stderr says `gita: 'wat' not found at HEAD`.

**Code:**

- `src/gita/lookup.py` (new):
  - `Symbol` dataclass — fields above.
  - `Ambiguous`, `NotFound` exceptions.
  - `get(root, name, *, rev="HEAD") -> Symbol`:
    1. Parse `rev`'s tree with `parse.parse_module` per `.py` file.
    2. Try `parse.find` per module; collect all matches.
    3. 0 matches: if `rev == "HEAD"` raise `NotFound`. Otherwise, walk the manifest chain *from rev forward to HEAD* looking for a `rename_symbol` op where `to == name`; if found, restart the search at `rev` with the old name. Repeat at most once per call (one hop). Raise `NotFound` if no hop helps.
    4. 1 match: return it.
    5. >1 matches: raise `Ambiguous(candidates=[qualified_name(m) for m in matches])`.
- `src/gita/cli.py` — `_cmd_get` handler, plain + JSON renderers.
- `src/gita/_manifest.py:render_manifest` — unchanged.

**Refactor in this phase:** none required. Resist refactoring `history.walk` to take a direction parameter unless phase 2 actually needs it. (It doesn't — the rename walk is a separate, narrower scan.)

**Acceptance:** all tests above green; `gita get` works on this repo's own source (try `gita get build_for_refs`).

## phase 3 · `prove` + `last-proven` + display integration

**Why now:** the new pillar. Depends on phase 2 only for `--symbol` filter.

**Tests to add** — `tests/test_gita_proofs.py` (new):

- `test_prove_records_success` — `proofs.record(root, "pytest", cmd=["python", "-c", "exit(0)"])` writes `{commit, checks: {pytest: {ok: True, exit_code: 0, ...}}}` to `.git/gita/proofs/<HEAD>.json`.
- `test_prove_records_failure` — exit 1 → `ok: False`, exit_code 1 stored.
- `test_prove_truncates_output` — generate 100 KB of stdout; stored `stdout_head` is ≤4 KB, `stdout_tail` ≤4 KB, `truncated: True`.
- `test_prove_merges_into_existing_proofs` — record `pytest` then `mypy` on same commit; file contains both keys.
- `test_prove_overwrites_same_named_check` — record `pytest` twice; only the latest result remains. (Or: keep history — decide now. **Lock: overwrite.** Proofs are "latest known result for this check on this commit", not a log.)
- `test_prove_refuses_dirty_tree` — uncommitted changes present → exit non-zero, no file written. (Spec says proofs are commit-keyed; dirty trees would attach to a stale commit and lie.)
- `test_last_proven_returns_latest_green` — three commits, only middle has `pytest: ok`. `last_proven(root, "pytest")` returns the middle commit's sha.
- `test_last_proven_unfiltered_requires_all_recorded_checks_ok` — commit has `pytest: ok, mypy: fail`. `last_proven(root)` (no check name) skips it. Commit with `pytest: ok` only and no `mypy` *passes* (we don't invent failures for unrecorded checks).
- `test_last_proven_with_symbol_skips_commits_where_symbol_absent` — symbol `foo` exists in commits A & C, missing in B. Proofs ok on A, B, C. `last_proven(root, "pytest", symbol="foo")` returns C, not B.
- `test_last_proven_with_no_recorded_proofs_raises` — empty proofs dir → `NoProofs` exception (CLI maps to exit 3 with hint).

**Tests to add** — `tests/test_gita_cli.py`:

- `test_cli_prove_runs_command_and_records` — happy path, file exists after.
- `test_cli_prove_dirty_tree_errors` — exits non-zero, message on stderr.
- `test_cli_last_proven_prints_sha` — exit 0, sha on stdout.
- `test_cli_last_proven_empty_exits_with_hint` — exit 3, stderr suggests `gita prove`.
- `test_cli_symbol_log_shows_proof_glyphs` — three commits with mixed proof states; output contains `✓`, `✗`, `·` lines.
- `test_cli_explain_shows_proof_section` — `gita explain HEAD` includes a `proofs:` section when proofs exist; silent when none.

**Code:**

- `src/gita/proofs.py` (new):
  - `proofs_dir(root)`, `proof_path(root, sha)`.
  - `record(root, name, *, cmd, stdout_max=4096) -> ProofResult` — runs `subprocess.run`, captures, merges.
  - `read(root, sha) -> dict | None`.
  - `last_proven(root, name=None, *, symbol=None, ref="HEAD") -> str` — walks `gx.log_shas`, applies filters, raises `NoProofs` / `NotFound`.
- `src/gita/cli.py`:
  - `_cmd_prove` — parse `<name> -- <cmd...>`, refuse dirty tree (check `gx.status(root)` for non-empty), call `proofs.record`, exit with the recorded result's exit code so CI pipelines naturally surface failures.
  - `_cmd_last_proven` — print sha or exit 3 with hint.
  - Modify `_cmd_symbol_log` to read proofs per sha and prepend glyph.
- `src/gita/_manifest.py:render_manifest` — gains optional `proofs: dict | None` parameter; if provided renders a one-line summary `proofs: ✓ pytest  ✗ mypy`.
- `src/gita/history.py` — no change needed; proofs are queried separately from manifests so the substrate stays clean.

**Refactor in this phase:** lift the three-state glyph (`✓`/`✗`/`·`) into a tiny `_glyph(proof_dict) -> str` helper inside `proofs.py` so `symbol-log`, `explain`, and (later) MCP all use the same function. One place to change emoji.

**Acceptance:** all tests above green. Smoke test by hand: `gita prove pytest -- python -m pytest -q` on this repo; `gita last-proven pytest`; `gita symbol-log build_for_refs` shows the glyph.

## working rhythm

For each phase:

1. Open the test file(s) listed. Write *every* test stub for the phase first, all marked failing with a minimal `assert False, "todo"` body or a real expectation that can't pass yet. Run `pytest -q` — see the right number of red.
2. Implement the smallest slice that makes the *first* test green. Run full suite. Commit.
3. Next test. Repeat.
4. End of phase: green suite, no `# todo` left, no dead branches. Refactor if and only if the code smells. Commit the phase as one push.

Commit message convention (matches existing log):

```
phase N: <verb>: <one-line summary>
```

e.g. `phase 2: lookup: gita get walks renames backward one hop`.

## not in this plan (explicit)

- Speculative branching, intent metadata, multi-language parsers, signed proofs, `gita gc` for proof retention. All parked per v0.2 spec.
- README rewrite. The README gets updated once after phase 4 ships, in one focused commit, by someone who actually used the new commands for an hour.
